# 보고와 인수인계

## PR 보고 양식

PR 본문(`.github/pull_request_template.md`)은 네 항목을 채운다.

1. **요약**: 무엇을 왜 바꿨는지 2~3문장.
2. **변경 파일**: 목록. 모두 Issue의 수정 가능 경로 안에 있어야 한다.
3. **검증 결과**: Issue의 검증 방법에 적힌 명령을 실행하고, **명령과 실제 출력**을 붙인다. 실행하지 못한 것은 "미실행"과 이유를 적는다.
4. **가정·미해결**: 작업 중 세운 가정, 남은 문제, 규약에서 발견한 허점(제안은 별도 Issue로).

## 반려 기준

검토자는 다음 중 하나라도 해당하면 `status:changes-requested`로 바꾼다.

- 검증 결과가 "확인했다"뿐이고 명령·출력이 없다.
- 변경 파일이 선언된 수정 가능 경로를 벗어났다.
- 완료 조건 중 하나라도 충족되지 않았다.
- 보호 경로를 그것을 목표로 하지 않는 Issue에서 수정했다.
- 키·토큰이 포함되어 있다.
- 작성자가 자기 PR을 검토했다.

반려할 때는 어떤 항목이 왜 문제인지 PR 댓글에 한 줄씩 적는다.

## 인수인계 메모

세션이 끊기거나 다른 에이전트가 이어받을 때 Issue 댓글에 남긴다.

```
### 인수인계
- 완료한 것:
- 남은 것:
- 막힌 점:
- 다음 한 걸음:
```

받는 쪽은 Issue 본문과 이 메모만으로 이어서 작업할 수 있어야 한다.
