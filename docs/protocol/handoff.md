# 보고와 인수인계

## PR 보고 양식

PR 본문(`.github/pull_request_template.md`)은 네 항목을 채운다.

1. **요약**: 무엇을 왜 바꿨는지 2~3문장.
2. **변경 파일**: 목록. 모두 Issue의 수정 가능 경로 안에 있어야 한다.
3. **검증 결과**: Issue의 검증 방법에 적힌 명령을 실행하고, **명령과 실제 출력**을 붙인다. 실행하지 못한 것은 "미실행"과 이유를 적는다.
4. **가정·미해결**: 작업 중 세운 가정, 남은 문제, 규약에서 발견한 허점(제안은 별도 Issue로).

## 반려 기준

검토자는 다음 중 하나라도 해당하면 `status:changes-requested`로 바꾼다.

- 검증 결과가 "확인했다"뿐이고 명령·출력이 없다.
- 변경 파일이 선언된 수정 가능 경로를 벗어났다.
- 완료 조건 중 하나라도 충족되지 않았다.
- 보호 경로를 그것을 목표로 하지 않는 Issue에서 수정했다.
- 키·토큰이 포함되어 있다.
- 작성자가 자기 PR을 검토했다.

반려할 때는 어떤 항목이 왜 문제인지 PR 댓글에 한 줄씩 적는다.

## 에이전트별 예외

PR 본문을 통제할 수 없는 에이전트(예: Jules는 PR을 자동 생성한다)는 양식을 채울 수 없다. 이 경우 **지휘자가 Issue의 검증 명령을 직접 재현해 실제 출력을 PR 댓글로 남기면** "검증 결과 없음" 반려 사유는 충족한 것으로 본다. 에이전트의 자기 보고는 증거로 치지 않는다.

## 검증 명령 대체

에이전트 실행 환경에는 `origin/main` 같은 원격 참조가 없을 수 있다(`git diff origin/main...HEAD`가 `unknown revision`으로 실패한 사례가 있다). 그럴 때는 다음을 지킨다.

- 같은 목적의 명령으로 대체한다. 예: 체크아웃한 기준 커밋과 비교 `git diff --name-only <기준 커밋>...HEAD`.
- **대체했다는 사실과 이유를 보고에 적는다.** 실패한 원래 명령과 출력도 함께 적는다. 조용히 바꾸는 것은 반려 사유다.
- Issue 작성자는 검증 방법에 원격 참조 대신 `<기준 커밋>`을 쓴다.
- 검토자(지휘자)는 원격 참조가 있는 환경에서 원래 명령을 재현한다.

## 커밋 작성자

에이전트가 연결 도구(API)로 브랜치와 커밋을 게시하면 커밋의 작성자·커미터가 **사용자 계정**으로 기록된다. git 이력만으로는 어떤 에이전트가 썼는지 알 수 없으므로 다음으로 판단한다.

- 브랜치 접두어(`<에이전트>/<이슈번호>-슬러그`)
- PR 본문의 `작성 에이전트`·`기동 방식` 칸(PR 템플릿). 에이전트가 본문을 자동 생성하는 경우 그 서명(예: "PR created automatically by Jules")도 이 신호로 본다.
- 이 둘이 서로 맞지 않으면 검토자는 반려하고 사용자에게 알린다.
- **작성 에이전트 표기가 없으면**: 곧바로 반려하지 않는다. 검토자가 PR 댓글로 작성자(또는 사용자)에게 채우도록 요청한다. 본문을 통제할 수 없는 에이전트는 서명과 브랜치 접두어로 판단하고, 검토자가 그 판단을 PR 댓글에 남긴다. 접두어도 규약 형식이 아니면 반려한다.
- 에이전트 정의 파일의 기동 문구는 두 칸을 채우도록 요구한다. PR 본문을 통제할 수 없는 에이전트는 요청을 넣어도 반영되지 않을 수 있으며, 그 경우 위 규칙대로 서명과 브랜치 접두어로 판단한다.

## 관찰 기록

관찰 기록은 지휘자가 쓴다. 작성자는 자기 기록을 쓰지 않는다(자기 평가 금지, 규칙 11). 그래서 기록을 쓰는 사람은 PR 작성자에 따라 달라진다.

| PR 작성자 | 기록을 쓰는 사람 |
|---|---|
| Claude 외 에이전트 | 지휘자(Claude) |
| 지휘자(Claude) | 그 PR의 **독립 검토자**(Claude가 아닌 에이전트) 또는 사용자 |

독립 검토자가 쓰는 기록도 해당 `agents/<이름>.md`를 수정하므로, 그 수정은 보호 경로 규칙(규칙 3)에 따라 그것을 목표로 하는 Issue로 진행한다. 기록 항목은 날짜 / Issue / 규약 준수 / 범위 이탈 / 검증의 정직성이다.

## 인수인계 메모

세션이 끊기거나 다른 에이전트가 이어받을 때 Issue 댓글에 남긴다.

```
### 인수인계
- 완료한 것:
- 남은 것:
- 막힌 점:
- 다음 한 걸음:
```

받는 쪽은 Issue 본문과 이 메모만으로 이어서 작업할 수 있어야 한다.
