# 작업 수명주기

## Issue 필수 항목

| 항목 | 설명 |
|---|---|
| 목표 | 한 문단. 이 Issue만 읽고 작업할 수 있어야 한다(자기완결형). |
| type | `feature` / `refactor` / `fix` / `docs` |
| 규모 | S / M / L. 한 세션 안에 끝나는 크기가 되도록 쪼갠다. L이면 하위 Issue로 분해한다. |
| 수정 가능 경로 | 한 줄에 경로 하나. 비어 있으면 착수하지 않는다. |
| 완료 조건 | 검토자가 참/거짓을 판정할 수 있는 문장 |
| 검증 방법 | 실행할 명령과 기대 결과 |
| 선행 작업 | `depends on #N` (선택) |
| 예산 메모 | 사용량 한도나 시간 제약 (선택) |

## 상태 전이

| 현재 | 다음 | 누가 | 조건 |
|---|---|---|---|
| (없음) | `ready` | Claude | 배정 완료, 경로 겹침 없음, 선행 작업 `done` |
| `ready` | `in-progress` | 담당 에이전트 | 착수 댓글과 브랜치 생성 |
| `in-progress` | `review` | 담당 에이전트 | PR 열림 |
| `review` | `changes-requested` | 검토자 | 완료 조건 미충족 또는 규약 위반 |
| `changes-requested` | `in-progress` | 담당 에이전트 | 수정 시작 |
| `review` | `done` | 사용자 | PR 병합 |
| 어느 상태든 | `blocked` | 담당 에이전트 | 질문을 Issue에 남기고 멈춤 |
| `blocked` | 이전 상태 | Claude/사용자 | 답변 후 |

## 단계 규칙

1. **착수**: 에이전트당 `in-progress` Issue는 1개. 선행 Issue가 `done`이 아니면 착수하지 않는다.
2. **작업**: 선언된 경로 밖은 건드리지 않는다. 범위를 넘어야 하면 멈추고 Issue에 질문한다. 임의로 확장하지 않는다.
3. **보고**: PR에는 실행한 명령과 실제 출력을 적는다([handoff.md](handoff.md)).
4. **검토**: 자기 PR은 자기가 검토하지 않는다. Claude 외 에이전트의 PR은 Claude가, Claude의 PR은 다른 에이전트(또는 Gemini Code Assist 같은 자동 리뷰 앱)가 1차 검토한다.
5. **병합**: 사용자만 한다. main 직접 push 금지.

## Claude의 두 모드

- **지휘**: Issue 분해·배정, PR 검토, 규약 관리. 항상 먼저 처리한다. 검토 대기열이 구현 때문에 밀리면 안 된다.
- **구현**: Claude에게 배정된 Issue를 수행한다. 지휘 대기열이 비었을 때 진행한다. 다른 에이전트와 같은 수명주기와 규칙을 따른다.

Claude는 Issue 생성만으로는 깨어나지 않는다. 사용자가 세션을 열어 시작한다. PR에 활동 구독을 걸어 두면 리뷰·CI 이벤트로 세션이 깨어난다.

## 토큰·컨텍스트 관리

1. **컨텍스트 위생**: 진입 파일은 짧게 유지한다. Issue는 자기완결형으로 쓴다. 세션이 끊기면 Issue 댓글에 인수인계 메모를 남긴다.
2. **사용량 예산**: 규모와 예산 메모로 관리한다. 에이전트별 실사용 관찰은 `agents/<이름>.md`의 관찰 기록에 남긴다.
3. **API 비용**: 자동 기동(B단계) 도입 시 키별 사용 한도를 설정한다.
