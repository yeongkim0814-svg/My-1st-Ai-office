# 충돌 방지 규칙

1. **경로 선언제**: Issue의 "수정 가능 경로"가 겹치는 열린 Issue는 동시에 `in-progress`가 될 수 없다. 배정할 때 Claude가 검사하고, PR 검토 때 변경 파일이 선언 경로를 벗어났는지 한 번 더 확인한다.
2. **브랜치 격리와 main 보호**: 작업은 `<에이전트>/<이슈번호>-슬러그` 브랜치와 PR로만 들어온다. main 직접 push는 금지한다.
3. **보호 경로**: 아래 경로는 그것을 목표로 하는 Issue로만 수정한다. 에이전트는 작업 중 발견한 규약의 허점을 직접 고치지 않고 Issue로 제안한다.
   - `docs/protocol/`
   - `agents/`
   - `.github/`
   - `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`
4. **공유 파일**: 락 파일·설정·인덱스처럼 여러 작업이 건드릴 파일은 단일 Issue 담당으로 둔다.
5. **의존성**: `depends on #N`이 `done`이 되기 전에는 착수하지 않는다.
6. **동시 작업 상한**: 에이전트당 `in-progress` Issue는 1개다.
7. **충돌 해결**: 나중에 병합하는 쪽이 base 브랜치를 자기 브랜치에 병합해 해결한다. 공유된 브랜치에 rebase·force push를 하지 않는다.
8. **검증의 정직성**: PR의 검증 결과에는 실행한 명령과 실제 출력을 적는다. 실행하지 못한 것은 "미실행"으로 적는다.
9. **비밀정보 금지**: 키·토큰을 커밋하지 않는다. 이 레포는 공개 레포다.
10. **리팩터링 독점 잠금**: `type:refactor` Issue는 경로가 겹치는 다른 `in-progress` Issue가 없을 때만 착수하고, 진행 중에는 그 경로의 새 착수를 막는다. 목표는 동작 보존이며, 전후에 같은 검증 명령을 돌린 출력을 PR에 첨부한다. 큰 구조 변경은 단계별 Issue로 쪼갠다.
11. **자기 검토 금지**: 어떤 에이전트도 자기 PR을 검토하지 않는다(Claude 포함).
