# Gemini

## 강점
초기 가설이며 관찰 기록으로 갱신한다.

- Jules를 통한 비동기 구현 작업 (가설).
- Gemini Code Assist 앱을 통한 PR 보조 리뷰.

## 맡기지 말 일
- 자기가 쓴 PR의 검토 (자기 검토 금지).
- 규약 파일(`docs/protocol/`, `agents/`, `.github/`, 진입 파일) 수정. 허점은 Issue로 제안한다.
- 병합.

## 쓰기 허용 경로
Issue가 선언한 경로뿐이다.

## 브랜치 접두어
`gemini/` → `gemini/<이슈번호>-슬러그`

## 기동 방법
- **구현 (Jules)**: **사용자가 Jules 화면에서** 이 레포를 선택하고 표준 지시문을 입력한다. 지휘자는 GitHub에서 직접 시킬 수 없다(아래 알려진 특성).

  > AGENTS.md를 읽고 Issue #N을 수행하라.

- **수정 지시**: 검토에서 반려되면 지휘자의 PR 댓글을 사용자가 **Jules 화면의 후속 지시로 옮겨 전달**한다.
- **보조 리뷰**: Gemini Code Assist GitHub 앱을 설치하면 PR이 열릴 때 자동으로 검토한다. PR 댓글에 `/gemini review`를 달아 수동으로 호출할 수도 있다.
- **자동 기동 (B단계)**: `run-gemini-cli` GitHub Action으로 `@gemini-cli` 멘션 기동. 파일 수정·PR 생성이 가능한 구성인지 도입 전에 공식 문서로 확인하고, 보안 규칙(소유자·협업자 멘션만 허용, 최소 권한)을 적용한다.

## 알려진 특성 (Jules, 2026-10-15 시험 — Issue #2, PR #3)
1. **PR 본문을 자동 생성한다.** 고정 형식이라 PR 템플릿(요약 / 변경 파일 / 검증 결과 / 가정·미해결)이 적용되지 않고, 생성된 본문은 이후 작업 내용과 어긋날 수 있다. → 검증은 지휘자가 재현한다(`docs/protocol/handoff.md` "에이전트별 예외").
2. **GitHub 댓글 지시를 따르지 않는다.** "작업을 시작한 사용자의 지시만 따른다"고 밝힌다. 지휘자의 리뷰 댓글에 반응하지 않았다.
3. **읽는 범위가 넓다.** 진입 파일뿐 아니라 설계·계획 문서도 읽고, 그 문장을 Issue의 경로 제한보다 우선 적용해 보호 경로를 수정했다. → `AGENTS.md`의 우선순위 규칙으로 보강했다.
4. **작업 전 계획 승인 단계가 있다.** 사용자는 계획의 파일 목록이 Issue의 수정 가능 경로와 일치하는지 승인 전에 확인한다.
5. Issue 착수 댓글과 `status:*` 라벨 변경은 하지 않았다. 상태 라벨은 지휘자가 바꾼다.
