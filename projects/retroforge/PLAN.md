> 작성: Claude (Issue #15) / 기준일: 2026-10-16
> 원안: 외부 도구(GPT)가 만든 v0.1. 이 레포의 협업 규약과 실제 환경에 맞게 고쳤다.

## 0. 이 문서의 위치와 원칙

1. **이 문서는 증명이 아니라 가설이다.** Court 판정, 모델의 추측, 조회수는 시장 수요의 증거가 아니다. 실제 사람의 반응과 구매만 증거다.
2. 확인하지 못한 연동·도구·사실을 확인한 것처럼 쓰지 않는다. 확인 수준을 표기한다(`research/sales-channels.md` 참고).
3. 사용자 승인 없이 지출, 계정 개설, 게시, 외부 전송을 하지 않는다. 판매자의 나이·결제 자격 요건을 우회하지 않는다.
4. 구현 작업은 이 레포의 규약(`AGENTS.md`, `docs/protocol/`)을 따른다. 이 문서는 규약을 바꾸지 않는다.
5. 공개 레포이므로 개인 신상, 정산 정보, **Pro 소스**를 이 레포에 두지 않는다.

| 단계 | 판결 조건 | 할 일 | 담당 | 완료 기준 |
|---|---|---|---|---|
| 0-1 | 판매처·정산 | 공식 문서 원문으로 정산 방식, 세금 양식, 나이 조항, 수수료 확인. 노트의 △·✕를 ◎로 올림 | 사용자 확인 + Claude(네트워크 허용 시) | `sales-channels.md`의 핵심 항목이 모두 ◎ 또는 "해당 없음" |

| 0-5 | 산수 | 순수익 계산에 실제 수수료·세율 반영, 목표 건수와 중간 지표 확정 | Claude | 계산 재현 가능, 목표 금액 확정(D4) |

## 4. 제품 범위 (v0.1에서 유지, 검증 후 확정)

**핵심 가치**: 복잡한 셰이더 지식 없이 기존 Godot 4 프로젝트에 레트로 3D 룩을 적용·설정·비교한다.

- **P0**: 설치·제거 안전성, 저해상도 픽셀화, 색상 양자화·디더링, 정점 스냅 등 간단한 PSX 효과, 거리 안개, 프리셋 3종, Before/After 데모, 설치·호환성 문서.
- **P1(검증 후)**: 에디터 도크, 머티리얼 일괄 변환, 사용자 프리셋 저장, 모바일·웹 최적화, 자동 시험.
- **P2(판매 검증 전 제외)**: 다른 효과 전부, 모든 버전·GPU 보증, 무손실 자동 변환, 월드 편집기, 서버·계정·구독.

**렌더러 정책**: 웹은 Compatibility + WebGL 2.0만 목표. PC Forward+와 Android 네이티브는 시험 완료 전에는 지원 확정 금지. 지원 범위는 "그 장비에서 검증됨"으로만 표기. 세부 원문은 v0.1(GPT 초안)의 3절을 따르며, Phase 0-6 결과로 확정한다.

차별화 후보(검증 전 가설): 웹·Android 같은 저사양 환경에서의 효과와 검증.

## 5. 협업 방식 (이 레포의 규약에 맞춤)

v0.1과 달라진 점이 핵심이다.

| 항목 | v0.1(GPT 초안) | v0.2 |
|---|---|---|
| 병합 | Claude가 결정 | **사용자만 병합.** Claude는 의견만 낸다 |
| 브랜치 | `feat/...`, `fix/...` | `<에이전트>/<이슈번호>-슬러그` |
| Issue 양식 | 자체 8항목 | `.github/ISSUE_TEMPLATE/task.yml` 사용 |
| 검토자 | Gemini 독립 리뷰 | 자기 PR은 자기가 검토하지 않음. 원본 규약(`docs/protocol/lifecycle.md` 4항)을 그대로 따른다: **Claude 외 에이전트(Codex, Jules)가 쓴 PR은 Claude가, Claude가 쓴 PR은 다른 에이전트(`@codex review` 또는 자동 리뷰 앱)가 1차 검토** |
| Gemini | 상시 독립 리뷰어 | Jules를 통한 작은 구현·문서 과업. 사용자가 Jules 화면에서 시작해야 함. 상시 리뷰어로 쓰지 않음 |
| Codex | 구현 | 구현은 채팅에서 "PR을 실제로 열어 달라"고 요청. 리뷰는 `@codex review` |
| 자동 검사 | 없음 | PR 규칙 검사 Action(알림 전용)이 브랜치명·`Closes #N`·수정 가능 경로·보호 경로를 알린다 |
| 보안 리뷰 | 가정 | Codex 보안 리뷰는 이 계정에서 동작하지 않았다. 의존하지 않는다 |
| 규약 문서 | 제품 레포에 새로 만듦 | 이 레포의 규약을 따르고, 제품 레포에는 얇은 `AGENTS.md`만 둔다 |

### 5.1 저장소 구성 (D3 근거)

| 저장소 | 공개 | 내용 |
|---|---|---|
| 이 워크스페이스(`My-1st-Ai-office`) | 공개 유지 | 협업 규약, 계획·조사 문서. Pro 소스 없음 |
| `game-asset` (생성됨) | **비공개** | Pro 소스, 정산·세무 메모 등 민감한 기록 |
| Lite 저장소 | 공개 (출시 때 생성) | 무료 Lite. 공식 Godot Asset Store 조건(스토어 표기와 `LICENSE` 일치) 충족. 오픈소스 여부는 D7 |

이 워크스페이스를 비공개로 바꾸지 않는 이유(확인 필요 사항 포함):
- 무료 계정에서는 비공개 레포에 브랜치 보호·Ruleset이 적용되지 않을 수 있다(계정 요금제 확인 필요, `[미확인]`). 지금 `main` 보호가 풀릴 수 있다.
- 비공개 레포는 Actions 무료 사용량이 제한된다.
- 계획·조사 문서는 민감하지 않다. 지켜야 할 것은 Pro 소스와 정산 정보이므로 그것만 분리하는 편이 비용이 작다.

비공개 레포에서도 에이전트가 일할 수 있는지(Codex 연결, Jules 설치, 이 세션의 접근)는 **아직 시험하지 않았다.** 빈 레포를 먼저 만들어 접근을 시험한다. 규약 파일은 이 워크스페이스를 참조하는 얇은 `AGENTS.md`만 둔다. 무료 계정의 비공개 레포에서 `main` 보호가 안 될 수 있으므로 병합은 사용자만 한다는 규칙으로 운영하고, PR 규칙 검사 Action을 복사해 알림으로 보완한다.

모든 PR에는 작성 에이전트, 기동 방식, 시험 근거, 변경 파일, 남은 위험, **외부 코드·에셋의 라이선스 출처**를 적는다. Pro 코드 레포(비공개)에도 같은 규약을 적용하되, 규약 파일은 이 레포를 참조한다.

## 9. 의사결정 규칙

- **GO**: 차별화 한 줄이 있고, 정산·세금·나이 요건이 확인되고, 산수상 목표가 비현실적이지 않고, 기술 가능성 시험을 통과.
- **PIVOT**: 차별화가 약하면 에셋 임포트·정리 도구, 테마 환경 패키지 등 다른 문제로 전환 검토.
- **NO-GO**: 정산이 불가능하거나, 핵심 렌더링이 시험 환경에서 작동하지 않거나, 수요 근거를 찾지 못하거나, 개선 비용이 기대 효익을 넘을 때.
