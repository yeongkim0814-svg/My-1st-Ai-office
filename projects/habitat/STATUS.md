# habitat 현재 상태 (STATUS)

새 세션이나 다른 에이전트가 맥락을 빠르게 잡기 위한 짧은 문서다. 결정은 `DECISIONS.md`, 계획은 `ROADMAP.md`가 원본이고, 이 문서는 요약과 "다음에 누가 무엇을 하는지"만 적는다.

## 정리 규칙

- 이 문서는 **한 화면 분량**을 유지한다.
- "최근 변경"은 최근 5줄만 둔다. 6번째부터는 지우지 않고 `docs/archive/habitat-status-YYYY-MM.md`로 옮긴다(월별 파일).
- 단계(P0~P5)가 바뀌거나 매월 첫 주간 점검 때 정리한다. 주간 점검이 이 문서와 실제 상태를 비교해 갱신을 제안한다.
- 개인 정보·금액을 쓰지 않는다. 기기는 "기준 기기 A"로만 적는다.

## 새 세션 시작 방법

긴 세션은 매 턴 대화 전체를 다시 읽어 비용이 커지므로 **작업 단위마다 세션을 나눈다**(사용자 제안, 2026-10-22). 상태는 저장소에 있으므로 대화 맥락 없이 이어 갈 수 있다.

1. 시작 말에 담을 것: 저장소(office / habitat), 작업 이름, 관련 Issue·PR 번호. 예: "habitat P1 4단계 터치 UI. #57, #59는 병합됨".
2. 에이전트는 `docs/protocol/README.md`를 가장 먼저 읽고(AGENTS.md 1번), 이어서 진입 파일(`AGENTS.md`, `CLAUDE.md`) → `agents/<이름>.md`(자기 역할) → 이 문서 → `DECISIONS.md`의 해당 D번호 순으로 읽는다(전부 읽지 않고 필요한 행만).
3. 작업은 Issue부터 연다(수정 가능 경로 명시). 브랜치는 `<에이전트>/<이슈번호>-<slug>`(예: Claude는 `claude/`).
4. 세션을 닫기 전에 대화에만 있는 확정을 DECISIONS에 기록하고, 이 문서의 "다음 할 일"을 갱신한다. 걸어 둔 점검 예약은 지운다.

세션 나누는 기준(제안, 미확정): office(결정 기록, 검토, 규약), habitat 구현은 P1 단계 하나당 세션 하나, 측정·디버깅은 따로.
