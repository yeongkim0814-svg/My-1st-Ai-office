# habitat(가칭) 로드맵

Issue #34. 결정은 `DECISIONS.md`에 있다. 이 문서는 **기간이 아니라 게이트**로 진행을 정의한다. 시간 예산은 사용자 참여 시간 기준의 추정이며, 주당 가용 시간 H로 나누어 주 단위로 환산한다(개인 일정은 채팅에서만 다룬다).

## 0. 원칙 (앞선 프로젝트의 실패에서 온 규칙)

| 반복된 문제 | 규칙 |
|---|---|
| 만든 뒤에야 핵심 가정을 확인함 | 가장 불확실한 것부터 **위험 스파이크**로 먼저 검증한다 |
| 중단 기준이 없었음 | 단계마다 **통과 기준과 중단·수정 기준**을 시작 전에 적는다 |
| 범위가 계속 커짐 | **범위 동결**: P3 통과 전에는 새 기능을 추가하지 않고 `IDEAS.md`에 적기만 한다 |
| 자체 평가만 함 | P3부터 단계마다 **처음 보는 사람 1명 이상**의 플레이를 관찰해 기록한다 |
| 에셋 출처 확인이 뒤늦음 | 첫 에셋부터 **출처 장부**(파일, 출처, 라이선스, 제작자, AI 사용 여부)를 남긴다 |
| 계획과 실제가 벌어져도 몰랐음 | 매주 일요일 **주간 점검**에서 계획 대비 실제 소모 시간과 게이트 상태를 비교한다 |

## 1. 단계

시간 예산은 버퍼 30%를 포함하지 않은 추정이다. 각 단계 종료 시 실제 소모와 비교해 다음 단계 예산을 고친다.

### P0 기반 (예산 약 35시간)

| 작업 | 담당(초안) | 산출물 |
|---|---|---|
| P0-1 저장소·에셋 규칙 결정(Q1), 출처 장부 양식 | Claude 제안 → 사용자 결정 | `DECISIONS.md` 갱신, 장부 양식 |
| P0-2 Codex 구현 위임 시험: 이슈/PR 댓글로 작은 GDScript 작업 1건을 맡겨 결과 품질과 한도 소모를 확인 | Claude 요청 → Codex | 시험 결과 기록 |
| S1 회전 거주구 표현 방식(월드 회전 vs 힘 적용)과 머리 위 반대쪽 구역 렌더링 | Codex 구현, Claude 검토 | 최소 장면 + 측정(FPS, 시각 확인) |
| S2 큰 원통 월드의 좌표 정밀도와 구간 모듈 이어 붙이기 | Codex 구현, Claude 검토 | 최소 장면 + 오차 측정 |
| S3 이전 프로토타입 격자 인벤토리 재사용 가능성(권리 포함, Q2) | 사용자 권리 확인, Codex 헤드리스 테스트 실행 | 재사용/재작성 판정 |
| S4 1인칭 컨트롤러 + 주민 시간표 + 길찾기 최소 장면 | Codex 구현, Claude 검토 | 최소 장면 |
| M0 그래픽 비교: 같은 테스트 장면(거주구역 거리, 오염구역 바위·식생, 머리 위 구역)을 2~3개 스타일로 | 사용자 방향, 에이전트 셰이더·조명 | 스크린샷 비교표 |

- **통과:** S1~S4가 각각 "통과" 또는 "실패 + 설계 수정안"으로 기록됨. 그래픽 후보가 2개 이하로 좁혀짐.
- **중단·수정:** S1이나 S2가 실패하면 원통 구조를 단순화(예: 원통 일부만 실제로 만들고 나머지는 배경)한다. S4가 실패하면 D10의 시간표를 시간대 고정 배치로 낮춘다.

### P1 거주구역 회색 박스 (예산 약 45시간)

- 실시간 시계와 밤낮 조명, 주민 3명의 시간대별 위치, 대화(대화 도구 선정 포함), 요청 데이터 구조, 요청 3개(일상 2, 거주구 특수 1), 판매.
- **통과:** 그래픽 없이 주민 3명과 요청 3개를 처음부터 끝까지 진행 가능. 저장·불러오기 동작.
- **중단·수정:** 요청 하나를 추가하는 데 코드 수정이 필요하면 데이터 구조를 다시 설계한다(요청은 데이터만으로 추가돼야 한다).

### P2 오염구역 회색 박스 (예산 약 60시간)

- 1인칭 이동, 회피(소리·시야), 적 1종, 제한적 전투 수단 1개, 격자 인벤토리와 보호 슬롯, 탈출 지점 2개, 사망과 가방 회수·소멸.
- **통과:** 레이드 1회를 완주하거나 죽고 회수하는 두 경로가 모두 동작. 헤드리스 테스트로 인벤토리·사망 규칙 검증.
- **중단·수정:** 회피가 재미없다고 판단되면(본인 기준 3회 플레이) 적 행동을 수정하고, 그래도 안 되면 전투 비중을 올리는 안을 논의한다.

### P3 순환 연결과 첫 외부 관찰 (예산 약 35시간)

- 출격 → 파밍 → 귀환 → 납품·판매 → 시간대 진행이 한 흐름으로 이어짐.
- **통과:** 본인 완주 + **처음 보는 사람 1명 이상이 설명 없이 한 순환을 완주**, 관찰 기록(막힌 곳, 재미있어한 곳).
- **중단·수정:** 외부 1명이 순환을 이해하지 못하면 P4로 가지 않고 순환을 고친다.

### P4 아트와 콘텐츠 (예산 약 90시간, P3 결과로 재추정)

- 그래픽 확정과 모듈 에셋, 거주구역 구획 확장, 주민·요청 추가, 오염구역 구간 추가, 소리.
- **통과:** 외부 1명 이상이 설명 없이 20분 이상 플레이.

### P5 공개 준비 (P4 결과로 계획)

- 외부 테스트 여러 명, 버그 정리, 공개 방식 결정. 판매·계정 개설은 판매자가 나이·결제 요건을 모두 충족할 때만 한다.

## 2. 에이전트·모델 배분 규칙

중요도와 토큰 사용량을 기준으로 정한다. 메인 세션의 모델은 사용자가 `/model`로 바꾼다. 서브에이전트와 외부 에이전트는 Claude가 아래 규칙으로 고른다.

| 작업 종류 | 담당 | 이유 |
|---|---|---|
| 설계 상의, 게이트 판정, 아키텍처, 리뷰 판정 | Claude 메인(상위 모델) | 판단 실수 비용이 가장 큼 |
| 문서 정리, 반복 편집, 이슈·PR 처리 | Claude 메인(중간 모델 권장) 또는 중간 모델 서브에이전트 | 판단보다 작업량 |
| 여러 파일을 훑는 검색·조사 | 읽기 전용 서브에이전트(가벼운 모델) | 결론만 받아 메인 맥락을 아낌 |
| 독립 검증(내 결론에 끌려가지 않는 검토) | 새 서브에이전트에 코드만 주고 결론은 주지 않음 | 확증 편향 방지 |
| GDScript 구현과 헤드리스 테스트 | Codex | 실행 환경(Godot 헤드리스)이 있음. P0-2에서 위임 품질 확인 |
| 1차 리뷰 | Codex(`@codex review`) | 작성자 ≠ 검토자 |
| 보조 리뷰 | Gemini Code Assist(`/gemini review`, Issue #32) | 필요할 때만 |
| 병합, 아트 방향 승인, 외부 플레이테스트, 지출, 공개 결정 | 사용자 | 사람만 할 수 있음 |

**토큰 절약 규칙**

- 도구 호출 몇 번으로 끝나는 확인은 서브에이전트를 쓰지 않고 직접 한다.
- 서로 독립인 조사·구현이 2개 이상일 때만 병렬 서브에이전트를 쓴다.
- Codex 호출은 PR당 리뷰 1회 + 수정 후 재검토 1회를 기본 상한으로 한다.
- 긴 대화는 단계가 끝날 때 결정을 이 문서와 `DECISIONS.md`에 옮기고 새 세션에서 이어 간다.

## 3. 주간 점검 연동

일요일 주간 점검은 이 문서의 단계별 통과 기준을 읽고 다음을 보고한다: 현재 단계와 남은 작업, 이번 주 실제 소모 시간(사용자 보고) 대 예산, 막힌 항목, 다음 주 행동 하나.

## 4. 이 로드맵의 한계

- 시간 예산은 경험치 없는 추정이다. P0의 스파이크 결과로 처음 보정한다.
- 에이전트 사용 한도(Codex 등)가 실제 병목이 될 수 있으며 아직 측정하지 않았다(P0-2).
- 그래픽 결정 전까지 P4 예산은 신뢰도가 낮다.
